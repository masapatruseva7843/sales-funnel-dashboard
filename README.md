# Sales Funnel Dashboard

Встроенный dashboard для Битрикс24 VibeCode. Показывает воронку сделок выбранного CRM-направления, ключевые показатели и последние сделки, доступные текущему пользователю согласно его CRM-правам.

## Что реализовано

- Сводка по каждой стадии выбранной воронки: количество сделок и сумма.
- Сумма открытых сделок, количество выигранных сделок и средний чек выигранных сделок.
- До 20 последних сделок, упорядоченных от новых к старым: название, сумма, стадия и ответственный.
- Выбор направления сделки (`categoryId`), по умолчанию - основное направление.
- Независимые диапазоны по дате создания и дате закрытия. Все заполненные фильтры применяются совместно.
- Пустые диапазоны допустимы; одна дата становится нижней либо верхней границей. Некорректный диапазон «С > По» отклоняется backend.

## Архитектура и модель доступа

```text
Браузер внутри Битрикс24
        ↓ GET /api/dashboard
Backend приложения (BFF, порт 3000)
        ↓ Vibe API
CRM и пользователи Битрикс24
```

Browser не обращается к Vibe API напрямую. Gateway передаёт backend заголовок `X-Vibe-Authorization`; backend принимает только этот заголовок и направляет запросы к Vibe API от лица текущего авторизованного пользователя. `VIBE_APP_KEY` живёт только в server runtime environment. Ключи и session tokens не передаются во frontend, не сохраняются в browser storage и не логируются.

Приложение использует только read-операции CRM: поиск сделок, агрегаты, статусы стадий, направления и список ответственных. Операции создания, изменения и удаления CRM-сущностей отсутствуют.

## Требования

- Node.js 20 или новее.
- VibeCode Black Hole server с tunnel на порт `3000`.
- Минимальные функциональные scopes приложения: `crm`, `user`, `placement`; для штатной аналитики ключ должен работать в режиме `READONLY`. Инфраструктурные возможности, если они нужны оператору deployment, не используются runtime-кодом dashboard.
- Размещение `LEFT_MENU` уже зарегистрировано для открытия dashboard внутри Битрикс24.

## Безопасная настройка окружения

1. Скопируйте `.env.example` в локальный `.env` только для временной настройки либо задайте переменную в менеджере секретов платформы.
2. Передайте `VIBE_APP_KEY` исключительно как server-side secret/runtime environment variable.
3. Не добавляйте `.env` в Git или исходный архив. Не помещайте значение ключа, `Authorization` или `vibe_session_` в код, логи, README либо browser storage.

Файл `.env.example` намеренно содержит только пустое имя переменной и безопасен для репозитория.

## Локальный запуск

```bash
npm install
npm start
```

Сервер слушает `3000`. Локальный запуск позволяет проверить интерфейс и валидацию, однако запросы к CRM требуют заголовок Gateway, который появляется только при открытии приложения через VibeCode/Битрикс24.

## Deployment на VibeCode

1. Подготовьте архив исходников только из `.gitignore`, `.env.example`, `README.md`, `package.json`, `server.js` и папки `public/`.
2. Убедитесь, что архив не содержит `.env`, IDE-метаданные, `node_modules`, логи или временные файлы.
3. Выберите существующий Black Hole server. Не меняйте network mode и access policy без отдельного решения владельца.
4. Задайте `VIBE_APP_KEY` как runtime secret сервера, установите Node.js 20, команду установки `npm install --omit=dev`, команду запуска `node server.js` и порт `3000`.
5. Выполните deployment. Для операции deployment требуется ключ с разрешением на инфраструктурные действия; после завершения переведите ключ аналитического приложения в `READONLY`, если это предусмотрено моделью ключей портала.
6. Откройте приложение внутри Битрикс24 из placement `LEFT_MENU` и проверьте загрузку данных от имени пользователя.

Deployment не требует и не должен создавать, изменять или удалять CRM-данные.

## Проверка для reviewer

1. Откройте **Sales Funnel Dashboard** из левого меню Битрикс24.
2. Убедитесь, что автоматически выбрано основное направление, и переключите направление при наличии нескольких воронок.
3. Проверьте стадии, KPI и последние сделки; данные должны отражать CRM-права текущего пользователя.
4. Проверьте фильтры по созданию и закрытию: пустые значения, одну границу и ошибку при «С > По».
5. Проверьте пустое состояние и сообщения для отсутствия CRM-доступа, истёкшей сессии и временных ошибок.
6. Убедитесь, что ключ приложения находится в `READONLY` для штатной эксплуатации.

## Ограничения

- Фильтр даты закрытия применяется ко всей выборке. Поэтому при его задании KPI «Сумма открытых» обычно равен нулю: у открытых сделок нет даты закрытия.
- Прямой переход по URL вне Битрикс24 не создаёт пользовательскую Gateway-сессию; dashboard следует открывать из `LEFT_MENU`.
- Видимость данных определяется CRM-правами пользователя, а не полем ответственного.
